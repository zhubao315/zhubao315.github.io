## 直接答案

用一条朴素链路：COROS 设备 → MCP → Python 同步 → SQLite → 静态数据与页面 → GitHub Pages。四个站点（健康、跑步、骑行、徒步）共享同一套定义，数据每天自动更新，历史全部保存在 Git 里；没有服务器，也没有数据库云服务。

## 为什么不是"第一张图"

个人数据项目最容易被第一张漂亮图表欺骗：样本小、指标好看，几周后不再更新。真正困难的是几年后仍能回答：这个数字怎么来的？那天为什么缺失？换设备后口径还一致吗？

量化生活的重点不是一次性可视化，而是让数据长期可查、可信、可解释。

## 系统怎么运转

1. **缺失保持缺失**：睡眠阶段缺失就是 null，不自动补零；质量报告公开缺失率、断档、重复键和稳健异常值。
2. **同步可以失败，但不能倒退**：每张表维护自己的同步水位，失败不推进水位，下次从缺口重读；写入使用 upsert，重拉不会用空值覆盖历史。
3. **同一定义服务所有界面**：滚动统计、基线、相关性与质量检查共用同一套 Python 定义，面板、Markdown 报告与 CSV 不会各说各话。
4. **四个独立站点**：健康、跑步、骑行、徒步各自发布，轨迹与 3D 地形由原始 FIT / GPX 生成，每天错峰同步。

## 实测与边界

项目案例记录健康数据从 2023-12-30 持续同步；站点持续更新，统计口径与日期以各站点数据文件为最终事实源。ACTIVE Watch 作为运营中枢负责巡检、共享 COROS 配额账本与品牌一致性，但它不发布面向用户的页面。

这类系统不适合需要实时协作或多人写入的场景；它适合一个人长期记录、离线可审计的数据档案。

## 常见问题

**需要服务器或数据库云服务吗？**
不需要。SQLite 是本地文件，页面静态托管在 GitHub Pages，历史都在 Git 里。

**COROS 有下载额度限制怎么办？**
ACTIVE Watch 使用租约式共享账本：同步前 reserve、同步后 reconcile，未用完当天归还；账本不可达时 fail-open 回退保守值，不中断同步。
