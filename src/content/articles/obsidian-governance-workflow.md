## 直接答案

不要一上来就让 AI 整理全部笔记。先跑只读诊断，拿到重复、断链、孤岛、缺失 frontmatter 与占位内容的清单；再按 G0–G7 准入与 L0–L7 分级决定哪些内容可以进入正式库；最后在明确授权下做移动、重命名与软归档，并保留恢复路径。重复执行这个循环，就是 OESA（观测 → 评估 → 固化 → 调用）。

## 为什么需要先诊断

长期知识库里最常见的问题不是"没有内容"，而是状态未知：

- 同一主题的多份副本，哪一份是最新？
- 断链指向的是失效文件，还是仅仅改名？
- 一个结论有没有来源与时间？
- 哪些归档仍被引用，哪些已经无人维护？

AI 可以快速生成整理建议，但如果没有证据，它也可能在没有来源时报告"已完成"。因此报告口径必须先立规矩：PASS 带时间、范围与方法；NOT_RUN 与 BLOCKED 不计入通过；AI 不能用自己的输出证明自己跑过。

## 可执行的流程

```bash
# 1. 只读扫描：先看诊断报告，不做任何写入
python3 scripts/audit.py --vault ./my-vault --dry-run

# 2. 按 G0–G7 准入规则判断哪些内容可进入正式库
# 3. 按 L0–L7 分级决定可见范围与调用方式

# 4. 需要变更时，先确认恢复路径，再显式授权
python3 scripts/apply.py --plan ./report.json --confirm
```

项目提供 8 个治理模块、4 份 OESA 规则、9 份 references、5 份模板和 7 个脚本；默认 dry-run，scaffold 拒绝非空目录，不覆盖、不移动、不删除。

## 实测结果与边界

仓库 25 项回归测试覆盖缺 frontmatter、断链、孤岛、占位、提示注入和 scaffold 安全边界。2026-11-26 这些是仓库公开事实，不是我对你本地知识库的扫描结果。

边界必须写清楚：扫描器是启发式的，不解析全部 Dataview、Canvas 或 Notion 属性；25 项 fixture 测试不证明一万篇规模的生产性能；Notion API 与 RAG 适配尚未实机联调。

## 失败情况

- 没有授权就执行写入：工具应拒绝，而不是"先做了再说"。
- 报告里出现 PASS 但没有时间、范围或方法：不能算通过。
- 用户把"收藏"当"资产"：诊断会显示大量孤岛与无来源结论，需要先做准入判断，而不是立刻优化检索。

## 常见问题

**删除权限在哪？**
没有。删除不在 AI 权限集合内；归档是软归档，必须可回滚。

**能直接接 RAG 吗？**
适配尚未实机联调。当前可靠的是治理流程与证据报告，不是向量检索效果。
