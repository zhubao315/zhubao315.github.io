## 直接答案

家庭记忆类 AI 产品的第一原则不是"生成得多好"，而是**资料归谁、谁能看、能否撤回**。可靠的做法是：每条记忆有明确归属、服务端强制隔离、AI 结果保留模型与 Prompt 版本、家庭协作分级授权、传承必须显式授权且可撤销、数据可完整导出。

## 为什么隐私是产品前提

人生故事包含照片、录音、家庭关系与逝者资料。一旦把这些内容交给一个只强调"AI 自动整理"的产品，用户失去的不只是隐私，还有对叙述本身的 control：模型改写了什么？谁看过？授权能否撤回？

Memoir 的设计前提写在 README 里：所有记忆有明确归属，服务端强制隔离；AI 结果可追溯，保存模型、Prompt 版本、输入引用与时间，不确定信息标记"待确认"，不编造。

## 六个中心如何分工

| 中心 | 作用 |
|---|---|
| Life Studio | 记忆、故事、照片与音视频概览，人生阶段进度 |
| Memory Vault | 多模态记忆库，时间线、人物地点关联、回收站与恢复 |
| Story Studio | 200 条中文问题库、AI 动态访谈、语音转写、7 种叙事风格、版本对比 |
| Family Circle | 家庭空间、邀请机制、五种角色分级授权 |
| Legacy Book | 章节编排、PDF / Markdown / JSON 导出、可撤销故事二维码 |
| Digital Legacy | 显式授权、指定分享范围、身份核验、人工审核、完整导出 |

关键在于：AI 不是自动把 private 资料变成 public 故事，而是帮你整理、给你版本、再由你决定分享范围。

## 可验证的边界

- 公开落地页不列出任何演示账号或密码；本地开发需自行注册并使用合成数据。
- 生产环境必须使用独立凭据与密钥管理，不复用测试数据。
- 存储支持本地（HMAC 签名 URL）与 S3 兼容方案；部署用 Docker Compose、Nginx 与 GitHub Actions。
- 项目 v1.0.0，Python 3.11+，MIT 协议；架构与安全审计文档公开在仓库中。

## 常见问题

**家庭资料会被默认共享给 AI 或其他家庭成员吗？**
不会。家庭空间通过邀请与五种角色分级授权；服务端强制隔离，每条记录可追溯到用户、空间、权限与来源。

**AI 写出来的故事算事实吗？**
不算。它保存来源与版本，不确定信息标记为待确认；最终核对仍由用户完成。

**授权之后还能撤回吗？**
可以。Digital Legacy 要求显式授权与指定分享范围，故事二维码可撤销，数据可完整导出。
